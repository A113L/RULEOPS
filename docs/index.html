Designed for large inputs

Spend memory on data, not overhead.

RULEOPS uses compact representations and bounded processing in several large-data paths. The goal is to reduce avoidable copies and Python-object overhead while keeping active datasets in RAM.

Read memory guide ↗
01

Shared wordlist memory

Valid word entries, including repeats, live in shared memory with a compact 64-bit offset table for direct access. Worker processes attach to shared data instead of receiving copies of huge Python wordlists.

02

Offset-based minimization

Rulest and standalone minimizer use fixed-width NumPy records with compact signatures and offsets into the original rule list. Later probe rounds focus on collisions rather than building large Python dictionaries for every rule.

03

Bounded genetic-search cache

Large-target GA work uses bounded samples, compact coverage bitmaps and a capped cross-generation cache to limit retained hit-map memory.

04

Reuse packed GPU inputs

GPU batches can reference prepared word bytes and reuse offsets and lengths, reducing repeated flattening and temporary data copies.

05

Shared worker inputs

Stage 0 workers receive small word-index ranges and attach to shared data structures, avoiding serialization of multi-million-entry wordlists.

Get started

Run RULEOPS locally.

Python 3.9+ is required. GPU-accelerated stages need a working OpenCL runtime and a compatible GPU driver. CSV-only analysis can run on CPU.

1 — Clone and install

Run these commands from a terminal.

git clone https://github.com/A113L/RULEOPS.git cd RULEOPS python -m pip install -r requirements.txt

2 — Start on Linux / macOS

Launch the local Control Center.

chmod +x start_gui.sh ./start_gui.sh

2 — Start on Windows

Run the included launcher from the project folder.

start_gui.bat
First launch: open the local URL printed in the terminal and set an application password of at least 12 characters. You can also run individual tools through their standalone CLI entry points.
Use responsibly. RULEOPS is intended for authorized password-security research and auditing on data you are permitted to test. The built-in server uses plain HTTP and is not designed for direct public-internet exposure. For remote access, use a private VPN or a TLS reverse proxy and restrict firewall access.
